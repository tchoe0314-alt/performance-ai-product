# Phase 0.4 — Maintainability closeout review

October 3, 2026. Complete for the verified local baseline. This document assesses the exact 0.4 roadmap requirements, not overall Phase 0 or release readiness.

## Requirement-to-owner review

| Roadmap requirement | Implemented responsibility boundary |
| --- | --- |
| Break oversized page components into focused modules | Dashboard panel routing, placement transactions, direct/queued plan lifecycle, editable design controls, saved-site restoration, and responsive workspace frame have dedicated owners. The dashboard composes these and existing domain hooks. |
| Break the preview/canvas into smaller systems | Pointer scheduling, CAD feedback/history, property/symbol commands, drawing/tool handlers, canvas shell, overlays and 3D rendering are separate from the preview composition root. |
| Separate interface from geometry/calculations | Workspace frame/panel router are presentation-only; object geometry, parking layout, interference, dependency planning, alternatives and payload conversion remain pure utilities. Backend engineering math is unchanged. |
| Centralize project-state operations | Synchronous `commitPlacementState`/`useDashboardPlacementState` own live object publication. Save/load/draft creation/restoration and guarded persistence are dedicated adapters. `dashboardProjectSaveQueue` serializes writes per workspace; default saves sample current serialized input at execution, and obsolete queued requests are rejected. All four duplicate named/aliased placement-ref writes were removed, including the transaction helper alias. |
| Centralize command execution | `dashboardCommandRouter` owns local command precedence and planner fallback; geometry commands share parsing/patch construction; adapters call existing canonical edits, batch/dependency transactions and plan executor. CAD grammar stays distinct from natural-language grammar, with the same accepted object-edit owner. |
| Centralize constraint evaluation | Active `siteInterference` and `liveConstraintFeedback` feed supported edit/dependency/layout checks; the unused `CivoraGeometryEngine` prototype is not a competing runtime authority. |
| Remove parallel sources of truth | Live placements publish the React display snapshot synchronously through one writer. Renderer geometry, pending proposals, comparison candidates and saved backend checkpoints remain explicitly non-authoritative for live edits. Legacy projects without metadata no longer inherit the prior workspace's source context. |
| Establish module ownership | This table and the architecture map identify presentation, input settings, canonical objects, commands, transaction planning, asynchronous execution, restoration and persistence owners. |
| Document core architecture | `phase-0-architecture.md` records the active path, compatibility boundaries, preserved prototypes and checkpoints. No legacy schema was silently migrated. |
| Resolve safe dependency upgrades | ESLint 9.39.4 → pinned 9.39.5 patch and its resolved dependencies; production packages are unchanged. Runtime/major upgrades were evaluated but not forced solely because newer versions exist. |
| Track remaining advisories | `phase-0-dependency-review.md` tracks the unpatched development-only braces chain, scope, mitigation, remediation trigger and incompatible major-downgrade suggestion. This criterion requires tracking, not inventing a nonexistent upstream patch. |

## Defects repaired while completing these boundaries

- Removed duplicate live placement writes in individual edit, custom geometry, combination and transaction commit.
- Prevented stale direct results, queued responses, preview completion and chat-decision/save continuation from publishing into another workspace.
- Cancelled the pending direct request on project open/New Project; old completion cannot clear a newer controller.
- Failed/queued/cancelled/stale runs no longer mark an engineering system fresh.
- Project-open errors and cleanup now honor request generation, so an old missing-project response cannot erase a newer restore or release its autosave suspension.
- Source-context restoration is project/request bound, clears missing diagnostics/map/detections and preserves explicitly assumed terrain instead of silently selecting survey.
- Save acknowledgements do not hydrate source context or accidentally trigger a project reopen before React commits identity. The latter regression includes an assertion that saving never calls the project-restore endpoint.
- Saved image uploads remain the fallback when a restored project has no map snapshot; missing images still clear, and image access still requires the existing authenticated upload adapter.
- Fixed intermittent save/reload regression where an older save could overwrite an edited position. Default saves now read the current serialized input; delayed chat/control timers call the current save adapter. Requests are ordered within one workspace, failed saves release the queue, and a new workspace does not wait on the old queue. Late errors/cleanup are generation-bound.
- Shared disclosure controls now publish click intent immediately rather than relying solely on a delayed native toggle event. Persistence checks wait for actual restoration and disclosure readiness. Native fixture type/dimension fields are explicit, and width/depth as well as position are asserted after reload.
- Earlier 0.4 work repaired typed Undo/Redo and precision-tool accessibility; its separate evidence remains in the architecture register.

Composition roots remain large: the dashboard is 5,826 lines and the preview remains approximately 2,934. Their size alone is not a proof of unsafe state ownership, nor is this a claim that every leaf component is now small. Further ergonomic prop grouping and domain-by-domain simplification remain maintenance backlog, not an excuse to bypass the implemented boundaries. There is no numeric maximum file size in the roadmap. Meaningful responsibility extraction, shared write/command/constraint ownership and preserved behavior are the assessed deliverables.

This is the existing compatibility model, not the universal Phase 1 object schema or a general multi-discipline dependency graph. Provider performance, engineering/design validity and external CAD compatibility are separate evidence. The tracked development-tool advisory remains a release risk; no risk waiver is implied.

Overall Phase 0 still needs formal platform disposition and Phase 0.5 exact deployed-artifact/environment/migration/backup/rollback verification. No deployment, purchase, push, or Phase 1 work is authorized or performed by this closeout.
